# Secretary Server

이 디렉터리는 클라이언트의 자연어 요청을 받아 일정 조회·추가·수정·삭제를 처리하고, 같은 HTTP 요청의 응답으로 자연어 답변을 반환하는 FastAPI 서버입니다. 별도의 파일 업로드나 결과 조회 요청은 필요하지 않습니다. LLM은 요청 유형 분류와 인자 추출에만 사용하며, 검증·타겟팅·충돌 판정과 DB 작업은 프로그램 로직이 담당합니다.

## 주요 기능

- FastAPI 기반 HTTP API 제공
- 한 번의 텍스트 요청으로 처리 결과까지 즉시 반환
- 자연어 질의 분류 및 DB 처리 라우팅
- 단발성 일정과 반복 일정 조회·추가·수정·삭제
- 사용자별 미완료 요청 상태를 유지하는 다중 턴 처리
- 만료된 데이터 정기 삭제 배치 처리

## 프로젝트 구조

- server.py: FastAPI 앱 진입점, 라우트 정의, 서버 생명주기 관리
- api_schemas.py: 텍스트 API 요청·응답 스키마
- database/: MySQL 연결 설정과 스키마 정의
- service/: 텍스트 분석과 DB 처리 로직

## 실행 전 준비

1. Python 패키지 설치
   - pip install -r requirements.txt
2. MySQL 서버 실행
   - 로컬 MySQL이 실행 중이어야 합니다.
3. 데이터베이스 초기화
   - database/schema.sql 을 실행해 meeting_DB를 생성합니다.
4. 환경 변수 설정
   - 프로젝트 루트에 .env 파일을 만들고 DB_PASSWORD를 설정합니다.
   - 예: DB_PASSWORD=your_password
5. Ollama 실행 (텍스트 처리 기능 사용 시)
   - Ollama가 로컬에서 실행 중이어야 하며, qwen2.5-coder:7b 모델이 준비되어 있어야 합니다.

## 실행 방법

서버 디렉터리에서 아래 명령으로 실행합니다.

```bash
python -m uvicorn server:app --host 0.0.0.0 --port 8000 --reload
```

## API 개요

### 텍스트 요청

- 경로: `POST /query/text`
- Content-Type: `application/json`
- 요청 필드
  - `user_id`: 사용자 식별자
  - `request_time`: 요청 시각. ISO 8601 형식
  - `user_text`: 일정 관리 자연어 요청 또는 서버 질문에 대한 후속 답변

```json
{
  "user_id": "user-1",
  "request_time": "2026-08-26T14:00:00+09:00",
  "user_text": "내일 오후 3시에 팀 회의 추가해줘"
}
```

서버는 요청 처리를 마친 뒤 같은 HTTP 응답으로 자연어 메시지를 반환합니다. 별도의 결과 조회 API는 사용하지 않습니다.

```json
{
  "message": "일정 삽입에 성공하였습니다."
}
```

필수 정보가 부족하면 서버가 추가 질문을 반환합니다. 클라이언트는 같은 `user_id`로 사용자의 답변을 다시 보내면 되고, 서버는 내부에 저장한 진행 상태를 이어서 처리합니다.

```json
{
  "message": "추가할 일정의 시작 날짜·시간을 알려주세요."
}
```

## 처리 흐름

1. 클라이언트가 `POST /query/text`로 사용자 ID, 요청 시각과 자연어를 전송합니다.
2. 진행 중인 요청이 있으면 서버가 사용자 ID에 해당하는 처리 상태를 불러옵니다.
3. `service/text_process.py`가 LLM을 사용해 요청 유형과 필요한 인자 후보를 추출합니다.
4. 프로그램 로직이 값을 검증하고 필요한 경우 추가 질문, 대상 선택 또는 충돌 확인 메시지를 만듭니다.
5. 실행 가능한 요청은 `service/db_process.py`가 MySQL에서 처리합니다.
6. 서버가 같은 HTTP 요청의 응답으로 자연어 메시지를 반환합니다.
7. 추가 답변이 필요하면 처리 상태를 유지하고, 완료 또는 실패하면 해당 상태를 제거합니다.

## 참고 사항

- 진행 중인 요청 상태는 서버 메모리에 저장되므로 서버를 재시작하면 초기화됩니다.
- 서버 실행 중에는 12시간 간격으로 만료된 일정/루틴 데이터를 정리하는 백그라운드 작업이 동작합니다.
